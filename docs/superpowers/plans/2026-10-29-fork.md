# Fork implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Take a session in two directions at once from the same point of its conversation (Manuel, 2026-10-29: "being able to take a session in one spot in two different directions simultaneously", such as asking which hardware to buy in one and taking the software another way in the other).

**Architecture:** `forkSession` starts a second orfoni session in the original's folder with `claude --resume=<original> --fork-session --session-id=<new> -- <first message>`, on the model and effort Claude Code last reported and the permission mode its hooks last carried. Until Claude Code writes the fork's transcript, the hub shows the conversation as it was forked. The session header's Fork button asks for the fork's first message and opens the fork.

**Tech Stack:** as before.

**Spec:** this plan and its decision log, `2026-10-29-fork-decisions.tsv`.

## Global Constraints

- **Claude Code 2.1.312.** `--session-id` names the fork when given with `--resume` and `--fork-session`. The fork's SessionStart hook reports `source: "fork"` under that ID. The fork's transcript holds the whole conversation, every entry under the fork's ID, and the original's transcript stays untouched. Claude Code writes the fork's transcript only with the fork's first message.
- **Settings.** No test, check, or fork may change `~/.claude/settings.json`; live checks compare its `model`, `effortLevel`, `modelSettings`, and `fastMode` before and after.
- No em dash characters anywhere. Markdown paragraphs stay on one line.

## Review Focus

- Forking a session that is working or waits on you. Expect a refusal that says to wait, and nothing started.
- Forking while the original goes on. Expect the fork to show the conversation as it was forked until its own transcript exists.
- A fork whose Claude Code ends before its first message is written. Expect it to fork the original again when it starts once more, not to start an empty conversation.
- A session that has not reported its model yet. Expect the fork on the user's default model, as a relaunch would be.
- The fork's title. Expect its first message with Claude Code's fork mark, so the list tells the two directions apart.
